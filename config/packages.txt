# Packages added to OpenWrt's defaults for the GL-AR750S (both builds).
# The device already brings kmod-usb2, kmod-usb-storage and block-mount.

# The receivers, the SDR libraries and tools, and their service
pirate-radio

# Ad blocking for the router's clients, through its DNS (dnsmasq). The Pirate Radio UI
# (Router tab) toggles it; this is the standalone adblock package, no LuCI app.
adblock

# Compressed RAM swap. On a 128 MB box carrying the SDR + recon stack this buys
# effective memory and keeps peaks (such as an adblock list load) away from the
# OOM killer. Pulls kmod-zram; in the full image it builds into the kernel.
zram-swap

# The MQTT broker (mosquitto) is optional and now lives in
# config/packages-extra.txt, added only to the "complete" build (PIRATE_EXTRAS=1).
# The lean default image leaves it out so nothing extra runs at boot.

# Packet capture, and a Wi-Fi analyzer for monitor mode
tcpdump-mini
horst

# The Pirate Radio web interface: the single-page UI served at the web root (/) plus
# all its rpcd/ubus backends — router basics, network recon (arp-scan, nmap,
# ip-full), SDR, packet capture, passive handshake capture and firmware
# flashing. This is the device's interface in place of LuCI. Pulls uhttpd,
# uhttpd-mod-ubus, rpcd, the recon tools and umdns, which answers to
# pirateradio.local (the hostname) over mDNS.
pirate-radio-ui

# GPS for the Wi-Fi survey's wardriving positions: gpsd and gpspipe, plus the
# kernel drivers a USB GPS enumerates with (CDC-ACM for u-blox; the common
# USB-serial chips). The full image's kernel is its own, so these kmods must
# be built in. gpsd stays idle until a GPS is plugged in.
gpsd
gpsd-clients
kmod-usb-acm
kmod-usb-serial
kmod-usb-serial-pl2303
kmod-usb-serial-cp210x
kmod-usb-serial-ftdi
kmod-usb-serial-ch341

# DreamPi: a Dreamcast dials a USB voice modem plugged in here (the modems a
# DreamPi uses) and gets online, through DreamPi's servers over PPP or through
# DCNet. Idle until a modem is plugged in; the Pirate Radio UI's DreamPi tab. Pulls
# ppp, which the image already has.
dreampi

# A Flipper Zero on the USB port: the Pirate Radio UI's Flipper tab shows its
# screen and buttons, its files and its details, as qFlipper does on a
# computer (pirate-flipper holds its RPC session). Idle until one is plugged
# in; its serial port is CDC-ACM, above.
pirate-flipper

# A MeshCore radio on the USB port (one running a companion build for USB,
# such as LilyGo's T-Echo): the Pirate Radio UI's Messenger tab, with its
# contacts, channels and messages, as MeshCore's app has them on a phone.
# With its GPS on, its position tags the Wi-Fi survey. Idle until one is
# plugged in.
pirate-meshcore

# A HackRF with a PortaPack on Mayhem firmware, in its device (console) mode,
# on the USB port: the Pirate Radio UI's PortaPack tab shows its screen,
# buttons, files, details and a firmware updater, as hackrf.app (MayhemHub)
# does on a computer (pirate-portapack speaks Mayhem's serial shell). It can
# also switch the PortaPack into HackRF mode for the SDR jobs. Idle until one
# is plugged in; its serial port is CDC-ACM, above.
pirate-portapack

# WireGuard, to tunnel back home over an untrusted uplink. The kernel module
# must be built into the full image (its kernel is its own). Configure the
# tunnel over SSH with uci/wg; the Pirate Radio UI has no WireGuard page yet.
kmod-wireguard
wireguard-tools

# The microSD card: exFAT (recommended), FAT32 or ext4
kmod-fs-exfat
kmod-fs-vfat
kmod-fs-ext4
kmod-nls-cp437
kmod-nls-iso8859-1
kmod-nls-utf8
exfat-mkfs
exfat-fsck

# USB flash drives and disks: plugged in, a drive is mounted and shared on the
# network (SMB: ksmbd, the kernel's server; wsdd2 lists the router in
# Windows' Network view) and on the Pirate Radio UI's Drives tab; pulled out,
# sharing stops (pirate-usb, in pirate-radio-ui). Neither server runs while
# no drive is plugged in. NTFS needs ntfs3 on top of the card's filesystems
# below; the full image's kernel is its own, so these kmods are built in.
ksmbd-server
wsdd2
kmod-fs-ntfs3

# The terminal in the browser (the Pirate Radio UI's Terminal page): ttyd, on
# the LAN only and behind the root password, as SSH is (pirate-access sets
# it up on first boot). Pulls libwebsockets, libuv and OpenSSL: about 5 MB.
ttyd

# lsusb, for checking what is plugged in
usbutils

# USB Wi-Fi adapters on the rt2800usb driver (Ralink RT3070, RT5370, RT5372;
# e.g. Panda PAU05/PAU06), for monitor mode. Brings its firmware. The full
# image's kernel is its own, so the driver has to be built in, not added
# with apk.
kmod-rt2800-usb

# A Bluetooth dongle on the USB port (the Pirate Radio UI's Bluetooth page):
# the devices around, as they advertise, each with its name, what kind of
# thing it is, its maker and how strongly it is heard. pirate-bluetooth has
# the adapter listen while a page looks (a passive scan: nothing is sent)
# and hands on what it reports; the page makes devices of that. The kernel's
# Bluetooth support and its driver for USB adapters (btusb, a package apart
# from kmod-bluetooth in OpenWrt 25.12) make an adapter (hci0) of the
# dongle; nothing of BlueZ is needed. The full image's kernel is its own, so
# the kmods are built in, not added with apk. Idle until a dongle is
# plugged in and a page looks.
kmod-bluetooth
kmod-btusb
pirate-bluetooth

# An ESP32 board on the USB port: pirate-esp says what chip it has and
# writes firmware to it, from the router, through the loader in the chip's
# ROM (as esptool does from a computer). Its USB-serial drivers are above.
# Nothing runs until it is asked.
pirate-esp

# An Android phone plugged into the USB port (the Pirate Radio UI's Phone
# tab): each of the phone's "USB controlled by" modes made useful on the
# router. USB debugging (adb) reads and switches the mode and reaches the
# phone's files; the kernel drivers below let the other modes work. The full
# image's kernel is its own, so these kmods are built in, not added with apk.
#   - tethering: modern Android (tested: Pixel, Android 17) tethers over CDC
#     NCM, not classic RNDIS; cdc-ether covers CDC-ECM devices. The phone then
#     appears as a WAN uplink.
#   - MIDI: usb-audio provides the ALSA rawmidi port.
#   - webcam: video-uvc gives /dev/video0, which ustreamer turns into an MJPEG
#     stream the browser shows.
# usb-audio and video-uvc each DEPEND ON (not select) a framework kmod -
# sound-core and video-core. Those are only pulled in automatically under
# ALL_KMODS; the ImageBuilder installs them by name, but this source build's
# `make defconfig` silently drops the leaf driver when its framework kmod is
# off. So name sound-core and video-core here too; the rest (media-controller,
# videobuf2, dma-buf, input-core) cascade through their `select`s.
kmod-usb-net-cdc-ncm
kmod-usb-net-rndis
kmod-usb-net-cdc-ether
kmod-sound-core
kmod-usb-audio
kmod-video-core
kmod-video-uvc
adb
ustreamer
